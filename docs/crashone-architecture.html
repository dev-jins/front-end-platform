1. The full picture

Crash One is a Vite + React app that hosts two independent views over one store: a React HUD (balance, bet slot, history, live bets, dialogs) and a Pixi canvas (the multiplier curve). Neither view talks to the network. They read a zustand store owned by the crash session in @fep/game-core/crash, and the HUD sends intents (bet, cancel, cash out) back to the session. The session talks to the outside world only through one interface, CrashTransport, and the app picks one of three implementations at startup from the launch URL.

ReactPixicore / contract planned dashed border = outside this repo
The five rules the code is built around
  1. One network seam. Everything above CrashTransport speaks the canonical crash protocol; provider quirks are translated below it (in a mapper or, later, the gateway).
  2. The server is the truth. The client never decides a crash or a payout. A cash-out shows the server's multiplier and win, not the number on screen when the player clicked.
  3. Snapshot, then patches. Every stream connection starts with a full snapshot; every later event patches it. Reconnecting is just "take the new snapshot".
  4. React never renders per frame. The HUD re-renders on state changes it selects; the curve is drawn imperatively by Pixi on its ticker, reading the store directly.
  5. Init once. bootGame runs outside React, so StrictMode's double effects can't call init twice (for Provider A a second init rotates the fingerprint and locks the tab out with error 112).

3. Boot sequence

index.html has two siblings: #game (the Pixi canvas) and #root (the React HUD, layered on top by styles.css). main.tsx calls bootGame(#game) and only then mounts React with the session. start() is fired but not awaited, so the HUD appears immediately and shows "Loading…" until init lands.

  • Why outside React: React StrictMode runs effects twice in dev. Booting in an effect would call init() twice. start() also guards itself (started flag), so a second call is a no-op.
  • Lane views wait for init: the number of lanes comes from init.capabilities.crash.lanes, so the views are built from a one-shot store subscription (it unsubscribes itself on first init).
  • Layout: lanes sit in one row, scaled down (never up) to fit the screen minus HUD_HEIGHT = 340 px reserved for the HUD, recalculated on renderer resize.
  • Boot failure (bad launch config, Pixi init) rejects bootGame; main.tsx renders the message in a role="alert" paragraph instead of the HUD.

6. Direct mode — Provider A from the browser

Until the gateway runs Connector A, the browser talks to Provider A directly. createDirectCrashTransport (in @fep/mapper-provider-a) turns Provider A's Game API and Mercure hub into the canonical CrashTransport, so nothing above it knows the difference.

What the direct transport does

  • Init parses nativeCrashInitSchema, keeps fingerprint and server for later, and builds the canonical init from the native balance plus PROVIDER_A_GAME_CONFIG (game id, decimals, bet limits, capabilities — things Provider A doesn't send).
  • Commands: toNativeCommand maps bet/cancelBet/cashout to /crash/bet, /crash/cancelBet, /crash/push, adds the fingerprint and drops lane (only non-lane games are supported). toCrashCommandResult maps the answer back.
  • Stream: one SSE connection with both topics as repeated topic params and the subscriber token as a Bearer header — that's why it reads SSE over fetch (subscribeSse) instead of EventSource, which can't send headers.

Why "resync" instead of mapping every event

Provider A's event payloads aren't documented. Only tick is translated directly. Every other event type schedules a /crash/myStats call (250 ms debounce, bursts merged; a call already running gets one follow-up) and the result becomes a fresh snapshot. Ticks are dropped until this connection's snapshot is out, because a snapshot must always come first. Every time the stream goes live (first connect or reconnect) it resyncs. seq is numbered locally and serverTime is the client clock, since Provider A sends neither.

7. Gateway mode — the production path

createGatewayCrashTransport is a thin client because the gateway already speaks canonical JSON:

  • POST /v1/sessions with Authorization: Bearer <launchToken> → CrashInit. The launch token is used only here. The transport keeps session.token and resolves stream.url against the gateway origin.
  • POST /v1/play with the session token → CrashCommandResult. The requestId in every command makes retries safe.
  • Stream: subscribeSse on stream.url with the session token; each message goes through parseCrashEvent, unknown types are reported to onError and skipped.
  • Non-2xx answers throw GameApiError(status, {kind: "unexpected", body}).

not built The gateway service itself doesn't exist yet (multi-provider-gateway.html). The transport is unit tested against a fake fetch. Mapping the gateway's canonical error taxonomy is a TODO[techdebt].

8. Dev mock — playable without any backend

createDevCrashTransport (app dev/) generates a timeline when the page loads and plays it through the protocol's createMockCrashTransport, which replays events with setTimeout at their serverTime offsets.

  • 100 rounds: 5 s countdown, flight on m = e^(k·t) with k = ln2 / 7000 (doubles every 7 s, so it uses the exp curve), ticks every 100 ms, 3 s pause. Crash points follow 0.99 / (1 − r), capped at 50×; 2–4 fake players bet and some cash out.
  • play() answers against the same clock: bet only before startAt, one bet per round, balance checked (error 3), cash-out only while flying, paid at the formula's multiplier.
  • limits one lane, no auto cash-out, no myBetSettled (a lost bet clears at the next round), reload after 100 rounds.

9. Event pipeline — from bytes to pixels

Batching matters because a ticks-only provider can send many events per frame and a reconnect can deliver a burst. The queue keeps each event's arrival time; the reducer uses it to estimate the server clock offset. The flush uses setTimeout(16), not requestAnimationFrame, on purpose: rAF stops in a hidden tab, and the queue would grow without bound until the tab came back.

applyCrashEvent(state, event, receivedAt)

  • Dedupe: any non-snapshot event with seq ≤ lastSeq is a repeat after a reconnect and is ignored. A snapshot always applies and resets lastSeq, so a new connection is always accepted.
  • Clock offset: sample serverTime − receivedAt; keep the largest. Delivery delay only makes the sample smaller than the true offset, so the max is the best estimate.
  • Snapshot replaces lanes, history, top wins, my bets and balance, but keeps each lane's pending command, so a reconnect during a bet doesn't unlock the button.
  • Missed round start: an event for a roundId the lane hasn't seen starts that round first (startLaneRound), then applies.
  • Unknown lanes (not in the snapshot) are ignored.

12. Session & intents

createCrashSession is the only thing that writes the store and calls the transport. Each intent returns Promise<boolean>: false means "not allowed now, nothing was sent"; true means a command was sent (its failure shows as an error, not as false).

IntentAllowed when (on top of readyLane)On success
bet(lane, amount, autoCashout?) lane in countdown (any phase if betWhileRunning: "nextRound"), no myBet, isAllowedBet: numeric amount within bets.min…max; auto cash-out only if the provider has it and ≥ its minbalance; myBet from the result
cancelBet(lane)lane in countdown with a myBetbalance; myBet = null
cashout(lane)lane running, myBet for this roundId, not cashed out yet balance; myBet.cashout = server's multiplier and win
dismissError()session not overerror = null

readyLane(lane) is the common gate: session ready, connection live, no open error, the lane exists and has no command pending. send() sets pending, awaits transport.play, writes the balance and the lane patch, and clears pending on success and on failure. pending drives the "Sending…" button and blocks double clicks. Every command gets a fresh requestId (crypto.randomUUID(), injectable for tests, like now and scheduleFlush).

14. Rendering the multiplier

Per frame — toCrashFrame

  • starting: 1.00, nothing drawn but the caption "Next round".
  • countdown: 1.00 and countdownEndsAt − serverNow → "Starts in 3.2s".
  • running with an exp curve: e^(k·elapsed) from startAt, never below the last tick — the tick floor corrects a wrong clock offset.
  • running, ticks only: the interpolated value, else the last tick.
  • crashed: the crash point, in red.

Smoothness helpers

  • TickInterpolator: draws one tick behind, easing from the previous tick to the latest over the gap between them. Smooth, and never shows a value the server hasn't sent.
  • CurveTrace: keeps one point per 50 ms plus a provisional head point that moves every frame, so the tip is exact without the list growing at frame rate.
  • curveViewport: auto-zoom from 8 s × 2× upward, keeping the head at about 80% of each axis.
  • Cash-out marker: the first trace point at or above the server's cash-out multiplier.
placeholder art The lane view is a line, a dot, a big number and a caption on a 720×405 panel. Game art (Spine object, particles) per crash game is still to come. Pixi scene files are excluded from the coverage floor; the math they call (toCrashFrame, interpolator, trace, viewport, screen mapping) is unit tested.

15. HUD

  • Frame (CrashHud): balance, recent crash points (≥ 2× highlighted), a "Connecting… / Reconnecting…" banner while not live, one BetSlot per lane, live bets (only if capabilities.liveBets), top wins (only if any), and the error Dialog. Before init it shows "Loading…" with aria-busy.
  • canAct = session ready ∧ stream live ∧ no error. It gates every button and input.
  • One button per lane, its action following the round: Sending… (pending) → Cashed out $X → Cancel (countdown with a bet) → Cash out $amount×multiplier (running, bet for this round) → Waiting for round → Bet $X / Wait for next round. The bet button is enabled only when isAllowedBet passes, the same check the session uses.
  • Inputs: amount (defaults to bets.default) and auto cash-out (default 2.00, shown only if the provider supports it). Editable only with no bet and nothing pending.
  • Money is formatted with formatMoney using the init currency and decimals; the cash-out preview uses decimal-string multiplication, not floats.
  • i18n strings are inline English until packages/i18n lands.
