1. System context

The client is a thin renderer. All game math, balance and step sequencing live on the server; the client only knows the sessionKey from the launch URL and the fingerprint from init.

Dashed = optional or not exposed to the client. The operator-platform link is inferred from balance, externalFreespins and the pass-through spinSpeed; the doc does not describe it directly.

2. Session lifecycle & device binding

Game init issues a new fingerprint on every call and invalidates the previous one. That is the single-device lock: opening the game again kills the first copy with error 112. Call init once per game start, not before each action.

Demo session

Never expires. user is null, tournaments are empty, screenshots are not stored.

Real-money session

Expires 1 month after the last action (1 week for some operators). Every action slides the deadline.

Expired → 109

POST actions: http 422. Game init: inside the 200 payload. Unknown key: http 404.

State held by client

Action responses don't repeat fingerprint or sessionKey — keep them from init.

3. Server-driven game flow

The client never decides what comes next. Each response carries currentStep (just played) and nextStep (endpoint to call). mode is spin in the base game and freespin during a series. Calling the wrong endpoint is rejected with the step's error code.

8. Error model

Errors arrive through five different channels — the client must branch on HTTP status and payload shape.

200 + error fields

Game init only. errorCode/Level/Message merged into payload; tournament fields omitted. E.g. 109, 111, 300.

422 business error

{errorCode, errorLevel, errorMessage} on rejected actions. Message is localized.

400 validation

Array of {code, message, field}. Empty body = {}, so it fails here.

422 parse error

{error: "Syntax error"} when the body is not valid JSON.

404

Unknown session key / lobby key / sysname. Screenshot GET when none exists.

Never fails

Screenshot POST is always 200 {saved, roundId}; /stat is always empty 200.

9. Client implementation gotchas

  • Money is strings. Amounts, wins, bets are numeric strings — parse with a decimal-safe type. bets[] items may be number or string.
  • extra is [] (empty array, not object) outside freespin/bonus modes. Guard before reading keys.
  • Init once. Re-calling init rotates the fingerprint and can lock out your own tab.
  • Popups are one-shot. tournamentStartPopup / tournamentWinnerPopup are delivered once, then null — show them immediately.
  • lines must be a JSON integer in /spin; bet accepts string or number. /buy rejects lines; /freespin ignores bet.
  • userData.place can be the string "-" instead of an integer.
  • socials has two shapes: {nickname} or {needToRequestNickname}.
  • Index bases differ: reels/rows/cols are 1-based, reelIndex/symbolIndex/reelsWithSpecials are 0-based.
  • Per-game adapters are required for the 7 variant games — don't type GameState as one interface.
  • Screenshot attaches only to the last winning round, within 30 minutes.
