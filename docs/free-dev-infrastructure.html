Free Dev Infrastructure

How to run the whole Game Front stack (lobby, game clients, Game Gateway, Redis, Postgres, monitoring and CI) for testing at $0, so staging and prod later reuse the same images and config on paid servers. Companion to the API architecture, frontend and multi-provider gateway pages.

Recommendation in one view

One free VM + Cloudflare

An Oracle Cloud Always Free ARM server (4 OCPU, 24 GB) runs the gateway, Redis and Postgres with Docker Compose. Cloudflare serves the lobby, the game clients and the game files.

Same artifacts everywhere

Dev, staging and prod run the same container images and the same compose file. Only the server size and env vars change, so promoting is adding servers, not rewriting.

Test play only

Use demo sessions against the dev Game API. Free tiers have no SLA, and money must never move through them. Check each limit when you sign up; free tiers change often.

Setup steps

  1. Create the accounts

    • Oracle Cloud: asks for a card to verify you, but doesn't charge.
    • Cloudflare, GitHub, Grafana Cloud, Sentry.
    • A domain (about $10 a year, the only real cost). Without one, use *.pages.dev addresses and the ?lobby= setting in place of separate lobby hostnames.

  2. Create the server on Oracle Always Free

    • Choose the home region close to the providers (for example Frankfurt). The gateway page says to deploy near the providers, and you can't change the home region later.
    • Create an instance: shape VM.Standard.A1.Flex, 4 OCPU, 24 GB RAM, Ubuntu 24.04 (ARM), with your SSH key.
    • In the VCN security list, allow incoming TCP 22, 80 and 443.
    • Oracle's Ubuntu image also blocks those ports in its own firewall. Open them on the server and install Docker:
    sudo iptables -I INPUT 6 -p tcp -m multiport --dports 80,443 -j ACCEPT
sudo netfilter-persistent save
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER   # log out and back in

    Tip: upgrading the account to Pay-As-You-Go keeps the free resources at $0, stops Oracle reclaiming an idle free server, and makes "out of capacity" errors much rarer. Set a $1 budget alert to be safe.

  3. Point DNS at the server

    In Cloudflare DNS, add an A record api-dev.<domain> → the server's public IP with the proxy turned off (grey cloud). Caddy then gets its TLS certificate by itself.

  4. Start the stack

    Create /opt/dev/ on the server with these three files, then run docker compose up -d.

    /opt/dev/docker-compose.yml
    services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports: ["80:80", "443:443"]
    volumes: [./Caddyfile:/etc/caddy/Caddyfile, caddy:/data]
  gateway:
    image: ghcr.io/<org>/game-gateway:dev
    restart: unless-stopped
    env_file: .env
    depends_on: [redis, postgres]
  redis:
    image: redis:7
    restart: unless-stopped
    command: redis-server --appendonly yes
    volumes: [redis:/data]
  postgres:
    image: postgres:17
    restart: unless-stopped
    env_file: .env
    volumes: [pg:/var/lib/postgresql/data]
volumes: { caddy: {}, redis: {}, pg: {} }
    /opt/dev/Caddyfile
    api-dev.<domain> {
  reverse_proxy gateway:3000
}
    /opt/dev/.env (chmod 600, never in git)
    POSTGRES_USER=gateway
POSTGRES_PASSWORD=<random>
POSTGRES_DB=gateway
DATABASE_URL=postgres://gateway:<random>@postgres:5432/gateway
REDIS_URL=redis://redis:6379
PROVIDER_A_URL=https://<dev-game-api>/api/v1
OTEL_SERVICE_NAME=game-gateway-dev
OTEL_EXPORTER_OTLP_ENDPOINT=<from Grafana Cloud>
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Basic <token>

  5. Deploy the frontend on Cloudflare

    • Lobby: one Pages project for apps/lobby. Add lobby-a-dev.<domain>, lobby-b-dev.<domain> and so on as custom domains on that one project. This is the recommended runtime-profile model: one build, and each lobby resolves its profile from the hostname at startup.
    • Games: one Pages project whose build output has games/<clientId>/ folders, on games-dev.<domain>.
    • Game files: an R2 bucket on cdn-dev.<domain>. Downloads from R2 are free.
    • Connect each Pages project to the GitHub repo; Cloudflare builds on every push and gives each branch a preview URL.

  6. Set up CI for the gateway

    Build an arm64 image (the Oracle VM is ARM), push it to GHCR, then SSH in and restart. Add DEV_HOST and DEV_SSH_KEY as repository secrets.

    .github/workflows/gateway-dev.yml
    name: gateway-dev
on:
  push:
    branches: [main]
    paths: ["apps/gateway/**", "packages/**"]
permissions: { contents: read, packages: write }
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: docker/setup-qemu-action@v3
      - uses: docker/setup-buildx-action@v3
      - uses: docker/login-action@v3
        with: { registry: ghcr.io, username: "${{ github.actor }}", password: "${{ secrets.GITHUB_TOKEN }}" }
      - uses: docker/build-push-action@v6
        with:
          context: .
          file: apps/gateway/Dockerfile
          platforms: linux/arm64
          push: true
          tags: ghcr.io/${{ github.repository_owner }}/game-gateway:dev
      - uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.DEV_HOST }}
          username: ubuntu
          key: ${{ secrets.DEV_SSH_KEY }}
          script: cd /opt/dev && docker compose pull gateway && docker compose up -d

    If the image is private, run docker login ghcr.io once on the server with a read-only token. A private repo gets 2,000 free CI minutes a month, which is plenty for dev.

  7. Add monitoring

    • Gateway: the OTEL_* vars above send traces straight to Grafana Cloud. Tag spans with provider, gameId and roundId, as the gateway page asks. No collector container needed.
    • Frontend: add the Sentry SDK to the lobby and to game-core, with one project per environment.

  8. Keep secrets out of the repo

    Secrets live in /opt/dev/.env on the server and in GitHub Actions secrets. Provider keys and fingerprints stay on the gateway and never reach the browser, as the gateway design requires.

If Oracle doesn't work out

If signup fails or no ARM capacity is available, run the gateway on Render's free tier (it sleeps after 15 minutes idle, so the first request after a pause is slow), with Upstash Redis free and Neon Postgres free. Cloudflare, Grafana Cloud, Sentry and CI stay the same; only REDIS_URL and DATABASE_URL change.

Future: deploys with Argo CD

Once staging and prod run on Kubernetes, deploys move to Argo CD. Argo CD is open source (Apache 2.0, CNCF graduated) and free to run; you pay only for the cluster it runs on. It only deploys to Kubernetes, so it replaces the Compose and SSH step, not the image build.

How deploys change

  • CI still builds and pushes the image to GHCR.
  • CI then updates the image tag in a deploy repo (or folder) instead of SSH-ing to a server.
  • Argo CD sees the Git change and syncs the cluster to match.
  • Rollback is a Git revert.

One repo, one folder per environment

  • deploy/base/: gateway Deployment, Service, Ingress (Kustomize or Helm)
  • deploy/envs/dev/, staging/, prod/: tag, replicas, env vars
  • One Argo CD Application per environment
  • Dev and staging auto-sync; prod syncs on manual approval

Trying it in dev for free

  • Install k3s on the same Oracle VM, then Argo CD on it (about 1–2 GB RAM).
  • Do this only when the move to Kubernetes is decided; until then Compose is simpler.
  • Redis and Postgres stay outside Argo CD in staging and prod as managed services.
Install on the dev VM (when ready)

  name: game-gateway-staging

    targetRevision: main

  destination:
    server: https://kubernetes.default.svc
    namespace: game-gateway
  syncPolicy:
    automated: { prune: true, selfHeal: true }   # omit for prod: sync by hand
    syncOptions: [CreateNamespace=true]

Done when

  • https://api-dev.<domain> answers with a valid certificate
  • A lobby hostname loads and shows the catalog for its profile
  • Launching a game opens the client from games-dev in an iframe
  • A demo spin goes browser → gateway → dev Game API and back
  • Retrying a spin with the same requestId returns the stored result without a second bet
  • The spin shows up as a trace in Grafana Cloud
  • A push to main redeploys the gateway without manual steps
  • No secret appears in the repo or in the browser bundle
